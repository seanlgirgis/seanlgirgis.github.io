1. Foundations

A high-volume ingestion pipeline receives large streams of events, buffers bursts safely, validates schema and quality, and routes data to multiple consumers. In interviews, this topic tests whether you can design production-grade systems under load, not just list tools.

Senior framing: pipeline design starts with reliability and operational ownership, then tooling.
Jumping directly to product names before requirements usually signals shallow architecture thinking.

2. Requirements First

Start by clarifying throughput, event size, ordering needs, latency target, retention window, delivery guarantees, and downstream consumers. These constraints decide partitioning, storage strategy, and consumer architecture.

Requirement Design Impact
Peak events/sec Partition count, ingress scaling, consumer concurrency
Ordering scope Partition key strategy and replay complexity
Latency SLO Streaming vs micro-batch architecture
Retention period Broker storage horizon and object-store replay model

3. Architecture Pattern

A proven pattern is producers to ingress controls to durable event backbone to stream processing to serving sinks, with immutable raw landing in parallel.

Core Layers

LayerPurpose
Producer + ingressAuth, quota control, and initial validation
Event backboneDurable buffering and decoupling at scale
Stream processingEnrichment, normalization, deduplication, routing
Raw storageLong-window replay and audit history
Serving sinksWarehouses, search, alerting, operational APIs
Partition key quality determines both scale and ordering behavior. Treat it as a first-class decision.

4. Reliability and Replay

Failure is normal. Use idempotent writes, deterministic event IDs, dead letter queues, and replayable raw storage. Include bounded retries with jitter and backoff to avoid retry storms.

Exactly-once is usually limited to specific boundaries. Be explicit about where duplicates can still occur and how you mitigate them.

5. Schema and Governance

Use schema registry and compatibility checks to prevent silent contract breaks. Add producer contract tests, ownership definitions, and lineage tracking so failures are diagnosable and accountable.

Additive schema evolution is safest; type changes and removals need migration windows.

6. Performance and Cost

Cost and performance are linked. Poor partition strategy, tiny files, and repeated full reprocessing can make a system expensive and brittle. Optimize with compaction, incremental processing, and retention tiering.

Over-partitioning creates metadata overhead; under-partitioning creates lag and hot shards.

7. Interview Scenario

Scenario: design ingestion for global e-commerce events (clickstream, orders, inventory). Clarify SLOs, choose balanced partition keys, validate contracts at ingress, quarantine invalid events, process curated streams, and monitor freshness plus lag end-to-end.

Strong close: explain replay runbook for partition-scoped backfill after logic bugs or schema incidents.

Interview Q&A

Q: How do you handle duplicate events?
A: Use deterministic event IDs, idempotent sink writes, and dedup windows keyed by event and time boundaries.
Q: What causes consumer lag?
A: Hot partitions, slow downstream dependencies, inefficient serialization, and under-provisioned consumers are common causes.
Q: Why keep raw immutable storage?
A: It enables long-window replay, audits, and safe reprocessing beyond short broker retention limits.
Q: When would you choose micro-batch over pure streaming?
A: When near real-time is enough and you want lower operational complexity with predictable throughput-cost trade-offs.

Cheat Sheet

Partition Key
Field used to distribute load and preserve partition-local ordering.
Consumer Lag
Distance between produced and consumed offsets/time.
Backpressure
Flow control to protect systems during bursts.
DLQ
Dead letter queue for failed records and recovery workflows.
Replay
Reprocessing historical events from durable retained data.
Schema Registry
Versioned contract enforcement for producers and consumers.
Idempotency
Same logical event can be retried without duplicate outcomes.
Compaction
Merge small files/segments to improve read efficiency.
SLO
Explicit latency and reliability target tied to business value.
